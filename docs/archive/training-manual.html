00-00-00General

Introduction

1. Purpose

This manual gives a program of study for LLVM and MLIR. The program prepares you for the sessions about the Modular stack.

The Modular stack contains Mojo and MAX. Both use MLIR. The code then goes through LLVM to the CPU or the GPU.

2. Scope

This issue contains Week 0 and Week 1. Later revisions will add Week 2 to Week 13.

3. How to use this manual

  • Do the tasks in the sequence that this manual gives.
  • Do all the steps of a task before you start the next task.
  • When you complete a step, select its box. This browser keeps the record.
  • Do the check at the end of each week. If an answer is incorrect, do the related task again.

Table 5 · Week 0 questions

Q1What are the three phases of a classic compiler?
The front end, the optimizer and the back end. The front end reads the source code and makes an IR. The optimizer improves the IR. The back end makes machine code for one target.
Q2A shared IR connects N languages to M targets. How many front ends and back ends are necessary?
N front ends and M back ends. Without a shared IR, you can need N × M different compilers.
Q3In Part 2 of R1, the word “CUDA” refers to more than one thing. Give three of them.
For example: the parallel programming model and its language (CUDA C++). The software platform: the compiler, the libraries (for example cuBLAS and cuDNN) and the tools. The ecosystem and the brand around them.
Q4Why was MLIR made?
Many AI frameworks and hardware companies made their own compilers and IRs. They did the same work many times. MLIR gives one shared infrastructure for many IRs. These IRs are the dialects.
Q5Which file sets the memory limit of WSL2? Which command shows the memory in Ubuntu?
The file %UserProfile%\.wslconfig sets the limit. The command free -g shows the memory.
Q6Which LLVM major version did apt install?
On Ubuntu 24.04, it is LLVM 18. Your result is in step (5) of TASK 00-20-00-400-802.

class BinaryExprAST : public ExprAST {
  char Op;
  std::unique_ptr<ExprAST> LHS, RHS;

public:
  BinaryExprAST(char Op, std::unique_ptr<ExprAST> LHS,
                std::unique_ptr<ExprAST> RHS)
      : Op(Op), LHS(std::move(LHS)), RHS(std::move(RHS)) {}

  double eval(const Env &E) const override {
    double L = LHS->eval(E);
    double R = RHS->eval(E);
    switch (Op) {
    case '+': return L + R;
    case '-': return L - R;
    case '*': return L * R;
    case '/': return L / R;
    case '<': return L < R ? 1.0 : 0.0;
    default:
      std::fprintf(stderr, "error: unknown operator '%c'\n", Op);
      return 0.0;
    }
  }

  std::string str() const override {
    return "(" + LHS->str() + " " + Op + " " + RHS->str() + ")";
  }
};

TermDefinition
ModuleThe top-level unit of LLVM IR. It contains global variables and functions. One source file usually gives one module.
FunctionA list of basic blocks. The first block is the entry block.
Basic blockA sequence of instructions with one entry point. Only the last instruction can change the control flow.
TerminatorThe last instruction of a basic block, for example br or ret.
Control flow graph (CFG)The graph of the basic blocks of a function. Each edge is a possible jump from one block to a different block.
SSA formStatic single assignment. Each value has exactly one definition. A value does not change after its definition.
Phi nodeAn instruction at the start of a block. It selects a value that agrees with the previous block.
Virtual registerA name such as %add. LLVM IR has no limit on their number. The back end assigns real registers.
DominanceBlock A dominates block B when each path from the entry block to block B goes through block A.
PassA unit of work that examines or changes the IR, for example mem2reg.

Table 8 · Week 1 questions

Q1Why does the constructor of BinaryExprAST use std::move?
You cannot copy a std::unique_ptr. std::move moves the ownership of the child node into the member variable.
Q2Why does ExprAST have a virtual destructor?
The program deletes each node through a std::unique_ptr<ExprAST>. Without a virtual destructor, the destructor of the derived class does not run. The result is undefined behavior.
Q3What does CMAKE_EXPORT_COMPILE_COMMANDS=ON make? Which tool uses it?
It makes the file compile_commands.json. clangd uses it.
Q4How many basic blocks did @sum have at -O0? Give their names.
Five: entry, for.cond, for.body, for.inc and for.end.
Q5Why does Clang keep local variables in memory at -O0?
It keeps the front end simple. Clang does not have to make SSA form. Later, mem2reg (or sroa in -O2) makes the SSA form.
Q6What does %i.0 = phi i32 [ 0, %entry ], [ %inc, %for.inc ] do?
It selects 0 when the control comes from entry. It selects %inc when the control comes from for.inc.
Q7What did the -O2 pipeline do with the loop in @sum?
It removed the loop. SCEV calculated the result with a formula equal to n × (n − 1) / 2.
Q8Why did the float loop not vectorize without -ffast-math?
A vectorized reduction adds the values in a different sequence. Floating-point addition is not associative, thus the result can change. LLVM does not change the result without permission.
Q9What does LLVM use in place of dynamic_cast?
isa<>, cast<> and dyn_cast<>. Each class gives a classof() function. LLVM does not use the C++ RTTI.
Q10Which LLVM back end makes code for NVIDIA GPUs?
NVPTX. It makes PTX code. Then ptxas or the NVIDIA driver changes the PTX code into machine code for the GPU.
