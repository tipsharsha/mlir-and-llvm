TASK 01-20-00-200-801Study the structure of LLVM IR60 min

1. General

LLVM IR is the code representation in the middle of LLVM. Mojo code also becomes LLVM IR before it becomes machine code.

Table 7 gives the important terms. Figure 7 shows a function in LLVM IR.

2. Job set-up information

Tools and equipmentReferenced information
Web browserR9, R10, R13 (optional)
Table 7 · LLVM IR terms
TermDefinition
ModuleThe top-level unit of LLVM IR. It contains global variables and functions. One source file usually gives one module.
FunctionA list of basic blocks. The first block is the entry block.
Basic blockA sequence of instructions with one entry point. Only the last instruction can change the control flow.
TerminatorThe last instruction of a basic block, for example br or ret.
Control flow graph (CFG)The graph of the basic blocks of a function. Each edge is a possible jump from one block to a different block.
SSA formStatic single assignment. Each value has exactly one definition. A value does not change after its definition.
Phi nodeAn instruction at the start of a block. It selects a value that agrees with the previous block.
Virtual registerA name such as %add. LLVM IR has no limit on their number. The back end assigns real registers.
DominanceBlock A dominates block B when each path from the entry block to block B goes through block A.
PassA unit of work that examines or changes the IR, for example mem2reg.

TASK 01-20-00-700-801Make LLVM IR from C source code30 min

1. General

Clang can stop after it makes LLVM IR. At -O0, Clang keeps each local variable in memory with alloca, load and store.

This keeps the front end simple. Later passes change these memory operations into SSA values.

2. Job set-up information

Tools and equipmentReferenced information
Ubuntu shell, clang, a text editorR10

3. Procedure

  1. (1)
    Go to the work directory: 
    cd ~/lab/week-01
  2. (2)
    Make the file sum.c with the code from Figure 8.
  3. (3)
    Make the LLVM IR: 
    clang -O0 -Xclang -disable-O0-optnone -fno-discard-value-names -S -emit-llvm sum.c -o sum.ll
    NOTE:-disable-O0-optnone removes the optnone attribute. Without this option, opt does not change -O0 functions. -fno-discard-value-names keeps the variable names in the IR.
  4. (4)
    Open sum.ll in your editor.
  5. (5)
    Find the definition of the function @sum.
  6. (6)
    Find the alloca instructions in the entry block. Record the names of the three variables.
  7. (7)
    Find the load and store instructions in the loop.
  8. (8)
    Count the basic blocks in @sum. Record the number.
  9. (9)
    Count the lines that contain optnone: 
    grep -c optnone sum.ll
  10. (10)
    Make sure that the command shows 0.
TASK 01-20-00-700-802Apply the mem2reg pass and show the CFG30 min

1. General

The mem2reg pass changes local variables in memory into SSA values. It adds phi nodes where control paths join.

The dot-cfg pass writes the CFG of each function to a Graphviz file.

2. Job set-up information

Tools and equipmentReferenced information
Ubuntu shell, opt, dot, a web browserR11

3. Procedure

  1. (1)
    Apply the mem2reg pass: 
    opt -passes=mem2reg -S sum.ll -o sum.mem2reg.ll
  2. (2)
    Compare the two files: 
    diff -u sum.ll sum.mem2reg.ll | less
  3. (3)
    Count the memory instructions in the new file: 
    grep -cE 'alloca|load|store' sum.mem2reg.ll
  4. (4)
    Make sure that the command shows 0.
  5. (5)
    Find the phi nodes in the block for.cond. Compare them with Figure 7.
  6. (6)
    Write the CFG file: 
    opt -passes=dot-cfg -disable-output sum.mem2reg.ll
  7. (7)
    Make sure that the file .sum.dot is in the directory: 
    ls -a
    NOTE:The file name starts with a period. Thus, ls without -a does not show it.
  8. (8)
    Make an SVG drawing of the CFG: 
    dot -Tsvg .sum.dot -o sum-cfg.svg
  9. (9)
    Open the directory in Windows Explorer: 
    explorer.exe .
  10. (10)
    Open sum-cfg.svg in a web browser.
  11. (11)
    Find the edge from for.inc back to for.cond. This back edge makes the loop.
TASK 01-20-00-700-803Apply the -O2 pipeline and find the vectorized loop60 min

1. General

-O2 is a pipeline of many passes. In this task, you examine the pipeline.

Then you examine two results. LLVM removes the loop in sum. LLVM vectorizes the loop in dot.

2. Job set-up information

Tools and equipmentReferenced information
Ubuntu shell, clang, opt, dotR11, R12

3. Procedure

SUBTASK 01-20-00-700-001Examine the -O2 pipeline
  1. (1)
    Show the important passes of the -O2 pipeline: 
    opt -passes='default<O2>' -print-pipeline-passes -disable-output sum.ll | tr ',' '\n' | grep -E 'inline|instcombine|licm|loop-vectorize'
  2. (2)
    Make sure that the list contains inline, instcombine, licm and loop-vectorize.
    NOTE:Some pass names have options in angle brackets after the name.
  3. (3)
    OPTIONALShow each change that the pipeline makes. Find the first pass that changes @sum. 
    opt -passes='default<O2>' -print-changed -disable-output sum.ll 2>&1 | less
SUBTASK 01-20-00-700-002Optimize the loop in sum
  1. (4)
    Apply the -O2 pipeline: 
    opt -passes='default<O2>' -S sum.ll -o sum.O2.ll
  2. (5)
    Find the function @sum in sum.O2.ll.
  3. (6)
    Find the mul instruction. LLVM changed the loop into a formula for the sum.
  4. (7)

  5. (8)

  6. (9)
    Open sum-O2-cfg.svg in a web browser.
  7. (10)

NOTE:The scalar evolution analysis (SCEV) calculated the value of s at the end of the loop. Thus, LLVM did not need the loop.

NOTE:Floating-point addition is not associative. A different sequence of additions can give a slightly different result. -ffast-math permits the compiler to change the sequence. GPU kernels for AI must also make this decision.
